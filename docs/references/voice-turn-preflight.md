# Owner preflight: topic pacing and voice turns

Automated fixtures have not verified real provider availability, speech quality or latency. Run this with your own configured providers and permitted source. Airs has no cumulative per-study voice quota or daily guest voice-start quota; starting practice, sending a recording and generating speech can incur provider charges. Recorded takes remain bounded to two minutes, synthesized replies to 3,000 characters, and optional live calls retain individual duration, lease and output bounds. Topic timing is a practice clock, not a provider spending ceiling.

1. Open `https://app.useflowst.com/airs/new` after Flowst sign-in. Confirm Misu’s context, review one source, choose five minutes per topic and a three-minute break, then approve the plan.
2. During handoff, check Misu/Amina preparation, the required ten-second guided handoff (no countdown or skip), readable welcome, voice preparation and playback. No microphone should be active. If the browser blocks playback, use Play welcome. If preparation failed, use the available explicit Retry welcome voice action and inspect its specific error. Saved approval and welcome should survive an audio failure.
3. Choose Start conversation when ready. The practice clock starts; Amina’s first question is prepared. Open Conversation to read a saved reply while its speech loads. Captions and transcript are confined to that panel. Speaking follows actual playback. With ElevenLabs timestamp alignment, captions appear with speech; an untimed provider fallback appears when playback starts.
4. Choose Start recording explicitly, allow the microphone, explain briefly, stop, review and send. Unsent audio stays local. Check transcription, reply preparation, saved reply, voice preparation, speaking and waiting. Confirm the saved transcript/source references match your actual attempt.
5. Pause and resume: remaining practice time should be preserved. Reload should restore saved work, pause active practice and avoid autoplay or microphone capture.
6. Let the block finish. Finish sending or discard an existing take; new takes should wait. During recovery, the microphone is off. Skip break & continue is available; otherwise Resume remains an explicit choice after recovery. Existing learning evidence/recommendation gates determine topic progression; time alone cannot complete a topic.
7. Try denied microphone permission or blocked playback without repeatedly submitting a paid take. You should receive a clear outcome while retaining saved work. Do not repeatedly retry an uncertain paid result.

Record deployment/date, provider, whether captions matched actual speech, a measured latency observation and any error message. Keep recordings, context and provider keys private. Delete unwanted test records.

The standalone guest slice uses the same shared flow, but its existing hosting protection currently blocks signed-out access. Use local labelled fixtures for reproducibility; a silent browser fixture is not evidence of real Amina speech.

8. Replay a prepared response, reload and Replay again. It should reuse stored audio without dispatching or recording another synthesis request. If a provider, pending-work or playback error occurs, check the specific outcome and read the saved reply; an uncertain paid result must not trigger an automatic retry.
9. Confirm a source-evidenced checkpoint. Only successful saved confirmation should celebrate and fill the journey rail. Kai becomes available after every objective is confirmed with evidence.
10. Check setup, plan and welcome on a phone: the primary buttons should clear the host navigation without document scrolling. Long material should remain available in its focused reader.

If ElevenLabs rejects a request despite a remaining account balance, inspect Developers > Analytics > Request Log for the actual speech-to-text POST or text-to-speech POST. Dashboard GET requests for previews, analytics or agent summaries do not establish that a speech request succeeded. Check the workspace/account connected to the deployed API key and that key's separate credit limit and speech-to-text/text-to-speech permissions. API keys can have custom credit limits ([ElevenLabs documentation](https://elevenlabs.io/docs/overview/administration/workspaces/api-keys)). Free-tier deployment restrictions are also separate from a remaining balance ([ElevenLabs account documentation](https://elevenlabs.io/docs/overview/administration/account)). Correct the specific restriction before deliberately retrying; do not rotate keys, change networks or automatically repeat paid requests to evade provider restrictions. Misu/Kai reasoning and Amina reply generation use Groq; recorded practice uses ElevenLabs for transcription and speech.

After a provider account, key, model or voice-access repair, use **Retry after account update** on the saved reply. This explicitly requests speech for that same saved turn; it does not resend the learner's recording. Provider setup failures remain non-transient and never trigger an automatic paid retry. Reloading or ordinary replay can return the cached failure until this deliberate retry is selected. Storage authorization failures, expired guest audio and missing responses do not offer this account-recovery action.

The ElevenAgents subscription screen's included call minutes do not set recorded Airs practice time. Recorded practice uses Scribe transcription and text-to-speech separately. Free accounts cannot use Voice Library voices through the API even when they have credits remaining ([official voice eligibility](https://elevenlabs.io/docs/eleven-creative/voices/voice-library)). Resolve the selected voice's entitlement using a legitimately eligible voice or subscription; a new API key alone does not grant voice access.
