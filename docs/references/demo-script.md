# Demo script

## 60 seconds

- 0–10: A recent graduate needs to explain a concept for an interview, not just consume a summary.
- 10–25: Bring one permitted source. Show what was read and an omission; for video, show a timestamped speech transcript.
- 25–35: Show Misu's proposed objective and the learner's approval.
- 35–50: Play a real recorded example of the learner's explanation and Amina's specific feedback, or demonstrate live when configured.
- 50–60: Show a new hypothetical application and saved evidence. Name the shared GitHub reader and four-tool MCP used during development.

## 3–5 minutes

Follow the same journey with time to inspect attribution, attempt an explanation, ask for a hint, and apply the idea in a different situation. Explain that the app saves evidence of attempts and does not infer mastery from completion. Show the actual Codex/MCP review evidence and the reproducible repository.

## Honest fallback

Preflight the exact source and provider connection before recording. If a platform is unavailable, demonstrate a permitted supplied transcript and say so. The local fixture mode demonstrates source review and scripted planning; it is not evidence that a live transcript or voice call succeeded. Do not simulate a live response or call a scripted response a real model result.

Disclose the existing deployed foundation and identify what was built for this submission. Verify unauthenticated judge access; a Vercel login page is not an accessible demo.

### Show Misu’s contribution

On the plan screen, identify Misu’s avatar and planner role. Open “What this plan is based on”; show the chosen goal, scope, time and source grounding. Read the objective’s proposed plan explanation alongside its citation, then approve the plan. Show “Planned by Misu” in Amina’s voice room. Recommendations expose the saved attempts used in the review; they remain suggestions the learner can accept or decline. Fixture explanations are scripted demonstrations, not live inference evidence.

## Public entry and repository

Start at https://app.useflowst.com, sign in and select Airs. Open Airs continues in the same window into the standalone source journey. Airs may require its own sign-in; the handoff implements no SSO. Show Back to Flowst, source attribution, Misu’s plan and Amina’s real practice when its live preflight passes. The public submission is estheticallybawo/flowst-airs-bring-your-source, independently runnable with npm run demo; the parent Flowst repository remains private.
