# Misu-led setup and prepared handoff

Implemented in authenticated Flowst first, then extracted into this independent slice. Flowst uses its existing account boundary; this slice retains its signed guest boundary. No authentication settings were disabled.

## Journey

Misu introduction → exact self-description → editable understanding → reviewed source → goal and time → review or adjust plan → saved approval → prepared handoff → Amina welcome → explicit Start conversation.

Personal context is capped at 2,000 characters, proposed summaries at 700 and plan adjustments at 600. Context revisions and conditional writes reject stale interpretation or confirmation. Summary failure keeps the saved words and permits retry or continuation with those words. Returning and legacy profiles remain editable. The proposed summary becomes authoritative context only after learner confirmation.

Source adapters keep their attribution, limits and explicit paid-transcription initiation. Document preview does not start a plan. Misu drafts after source confirmation and preferences; regeneration produces a new draft requiring approval, and failure preserves the preceding draft.

## Activity and authority

Backend context and plan operations expose only safe phases, identifiers and revisions. UI polls while work is pending and labels completed work only after its service operation succeeds. No hidden reasoning is displayed. Thinking Orbs is an MIT canvas engine vendored at de85557ca220332586d070d8788c0e1d6e877a0d; the face remains the identity. Animation pauses offscreen and in hidden tabs, caps density at two, and uses static reduced-motion frames.

Approval saves the plan; it does not start practice. An idempotent welcome tied to the approved plan is prepared in the same workspace. Speech failure keeps readable text and Replay. Reload restores readiness without autoplay. Start conversation is the sole live-call/microphone action. Recorded practice remains available. Classroom handoff authority is unchanged.

## Verification boundary

Desktop/mobile fixture journeys verify editable context, source review, plan adjustment, preparation, failed welcome playback, reload without autoplay, and denied microphone access after Start. Unit tests cover stale revisions, interpretation failure, progress order, draft preservation, ownership and duplicate approvals. These checks do not establish live model quality, live voice success or longitudinal improvement. Paid provider checks remain owner preflight.
